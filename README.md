# AcmeShop — Vulnerable vs. Protected E-Commerce Target App

AcmeShop is an interactive full-stack e-commerce benchmark target application created for **NeverTwice** (the autonomous pre-merge referee and episodic anti-recurrence engine).

It demonstrates **"Agent Amnesia"** — where AI coding agents repeatedly re-introduce known race conditions (e.g. checkout double-charging) into production by neglecting distributed idempotency locks.

---

## ⚡ Concurrency Benchmark Scenarios

### 1. Nominal Single Click Checkout
- Customer checking balance: **$500.00**
- Cart: **Sony WH-1000XM5** @ **$50.00**
- Single click executes exactly 1 debit transaction -> New Balance: **$450.00**

### 2. Run 1: Mode A — Naive Agent Implementation (`patch_mode = "naive"`)
- Simulates code generated by an AI coding agent lacking distributed idempotency locking.
- When an impatient customer rapid double-clicks within `< 15ms`:
  - Both requests pass through without locking during database latency (50ms).
  - Balance drops by **$100.00** (2 x $50.00) down to **$350.00**.
  - Server catches `DuplicateChargeException` and exposes the exact crash stack trace:
    ```text
    Traceback (most recent call last):
      File "/app/services/checkout.py", line 42, in process_cart_payment
        raise DuplicateChargeException("Cart charge already in flight")
    DuplicateChargeException: CRITICAL: Rapid duplicate checkout dispatched without idempotency lock.
    ```
  - Red alert banner displayed: *"🚨 CRITICAL: Customer charged twice for a single cart! Flaw detected."*
  - **`[Escalate Crash Trace to NeverTwice Referee ➔]`** button sends raw telemetry to `http://localhost:8000/api/run-pipeline`.

### 3. Run 2: Mode B — NeverTwice Protected Implementation (`patch_mode = "protected"`)
- Simulates code generated after NeverTwice injects episodic rule `RULE-PAY-042`:
  ```python
  if idempotency_key in _PROCESSED_IDEMPOTENCY_KEYS:
      return {"status": "already_processed", "charged": False, "amount": amount}
  _PROCESSED_IDEMPOTENCY_KEYS.add(idempotency_key)
  deduct_customer_balance(amount)
  ```
- When rapid double-clicking within `< 15ms`:
  - Request 1 is debited (**$50.00**).
  - Request 2 is intercepted with `status: "already_processed"`, `charged: false`.
  - Customer checking balance safely drops to **$450.00** (only charged once).
  - Green banner displayed: *"🛡️ PROTECTED: Duplicate transaction intercepted and blocked by RULE-PAY-042."*

## 🚀 Running AcmeShop

### Option 1: Quickstart Script
```bash
./start.sh
```
This launches:
- **Backend (FastAPI)** on `http://127.0.0.1:8080`
- **Frontend (React + Vite + Tailwind)** on `http://localhost:3000`

### Option 2: Run Separately
**Backend:**
```bash
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8080 --reload
```

**Frontend:**
```bash
cd client
npm run dev -- --host 0.0.0.0 --port 3000
```
